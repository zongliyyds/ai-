# 本地多服务端口隔离：launcher 探活要验特征，不能只查端口

## 核心观点

本机同时跑多个本地 Web 程序时，**端口是共享资源，必须显式隔离**；而「服务是否已运行」的判断**不能只看端口是否被占**，必须探活一个服务独有的特征（如 `/health` 返回的 `app` 标识），否则会把别人的程序当成自己、stop 还会误杀对方。

## 现象（VaultMind 2026-09-20 实战）

- `D:\English study`（英语四级备考知识库，独立 FastAPI 程序）与 VaultMind **都写死 8000 端口**。
- 两者同时运行时：后启动的 `launcher.py` 只 `socket.connect_ex(8000)==0` 就判定「自己的服务已在运行」，直接开浏览器 → 打开的是**对方**的页面。
- `stop.bat` 用 `taskkill` 按 8000 端口/窗口标题杀进程 → 把**对方**服务误杀。

## 做法

1. **本地多服务先分配端口**：VaultMind 迁到 8001（`launcher.py` 的 `PORT` 一处常量 + 文档地址同步），英语四级保持 8000，两程序隔离。
2. **探活要验特征**：VaultMind 的 `launcher.py` 已正确——`health_ok()` 不只看端口，还请求 `/health` 并校验 `app == "vaultmind"` 才算「本服务就绪」，否则报「端口被其它程序占用」而非误开。英语四级的 `launcher.py` 缺这一步（只查端口），是隐患。
3. **stop 要精确到进程**：按「端口 + 特征」定位 PID 再 `taskkill /PID`，不要按端口/标题模糊杀。
4. **前端用相对路径**：`index.html` 走相对路径（`/search`、`/ask`）不硬编码端口，换端口零改动——这是端口可迁移的前提。

## 一句话总结

本地多服务：**端口显式隔离 + 探活验特征（不是验端口）+ stop 精确到 PID + 前端相对路径**；四件事凑齐，才能「正确打开不同程序」。

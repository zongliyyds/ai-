# 消融实验方法论：负结果也是结论

## 核心观点

消融实验的价值不在"证明每个组件都有效"，而在**量化每个组件到底贡献多少、哪些组件该砍**。负结果如实记录并给出归因，比"全绿报告"更有说服力。

## 实验纪律（VaultMind M6 实战）

1. **同一把尺**：全部实验同一份 gold 集、同一指标口径；基线行必须与官方基线精确一致（基线复现闸门），否则整份报告作废。
2. **只动待测组件，其余冻结**；变体用函数可选参数实现，默认值 = 基线行为 → 主链路零改动。
3. **分层看指标**：总体指标会掩盖结构性问题（本例 hard 档 58% vs easy 档 97% 差距巨大，很多实验的真相在分层里）。
4. **结论数据驱动**：报告脚本自动插值真实数字，重跑可复现，不写"看起来对"的空话。

## 六组结果一览（60 条 gold，hybrid 基线 R@5=0.8167）

| 实验 | 结果 | 结论 |
|---|---|---|
| BM25 / 向量 / RRF 单拆 | 0.7667 / 0.7500 / **0.8167** | 融合正增益 +0.05；但 R@1 融合反而低于纯向量（**顶部稀释**） |
| RRF k=20/60/100 | R@5 恒 0.8167 | 参数不敏感，无需调参 |
| 查询改写（规则/LLM） | -0.017 / -0.067 | **负结果不上线**：裸标题词就是最强信号，改写稀释它 |
| 标题加权重排 | easy 1.0000 / hard 0.3750 | 分层撕裂 → 需条件化（标题命中才加权） |
| 双链 1-hop 扩展 | +0.0000 | 中性 → 转「相关笔记推荐」，不进检索主链路 |
| 规模-延迟曲线 | 25%→100% 语料 290→286ms | 瓶颈=查询侧 embedding，暴力点积 <1ms → 零向量库成立 |

## 面试/简历口径

- "我做过六组消融，砍掉了查询改写和 1-hop 两个无效组件，量化了融合的顶部稀释现象"——比"我用了 RRF"强一个量级。

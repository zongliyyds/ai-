# 本地模型掉线：探活 + 结构化 503 + 前端优雅降级

> **核心观点**：本地服务型应用最常见的故障是**依赖进程掉了**（Ollama 没起、模型没拉、索引缺失）。此时后端抛异常 + 前端 `resp.json()`，用户只会看到一句 `SyntaxError: ... is not valid JSON`——**真因被两层错误掩盖**。

## 现象链（VaultMind，2026-09-17）

1. 页面提问 → `错误：SyntaxError: Unexpected token 'I', "Internal S"... is not valid JSON`
2. 查服务日志才见真因：`RuntimeError: 无法连接 Ollama（WinError 10061 积极拒绝）`
3. 三层叠加：Ollama 未运行 → `/ask` 未捕获异常 → FastAPI 500 纯文本 → 前端 `await r.json()` 抛 SyntaxError

## 修法（每层各一处）

| 层 | 做法 |
|---|---|
| 后端 | 捕获依赖异常 → **503 + 结构化 JSON** `{error, message, hint, detail}`；`hint` 直接给可复制的修复命令 |
| 健康检查 | `/health` **真实探活**（`status: ok|degraded`、`deps.ollama.ok`、`models`、`ready`）+ `/deps` 自检列出不可用项与修法 |
| 前端 | 统一请求封装：`raw = await r.text()` → `try { JSON.parse(raw) } catch {}`；进页面与每 30s 轮询 `/deps`，横幅提示「当前无法问答 + 怎么修」 |

## 教训

- **健康检查不能是常量**：永远返回 `{"status":"ok"}` 的探针等于没有探针。
- **错误也要有结构**：给前端的错误必须可解析；`hint`（可复制命令）比 `message` 更能让用户自救。
- **本地依赖掉线是常规分支**，不是异常分支——要写单测覆盖（打桩离线 → 断言 503 + JSON detail）。

# 开源打包红线：白名单 + 探针自动化

## 核心观点

**开源源码仓库前，打包/推送必须自动化校验"什么不该进去"**——靠人工检查必漏，靠 gitignore 也拦不住"某天手滑 add 了不该加的"。

## 做法（VaultMind M7 实战）

1. **白名单打包**（`scripts/package_repo.py`）：只复制明确清单内的目录/文件，而不是"排除清单"——默认不包含，比默认包含安全一个量级。
2. **内容脱敏**：评测集分发版剔除 `answer_points` 字段（原文摘录）；含摘录的文件（候选池、人读版、改写缓存）不进包。
3. **红线探针（打包后扫描，命中即拒绝产出）**：
   - 文件名含私有库名 → FAIL；
   - 正文匹配手机号正则 `1[3-9]\d{9}` → FAIL；
   - 结构探针：摘录类文件不得出现在包内、gold 不得含 answer_points。
4. **口径校准**：项目文档**合法引用配置路径**不算泄露（路径是配置说明）；真正红线是**内容**（笔记正文、手机号等 PII）。探针只拦内容不拦路径引用，否则自缚手脚。
5. 配套：`git push` 前 `.gitignore` 必须覆盖 `data/`（索引派生）；仓库 README 声明"知识库内容不在仓库中"。

## 反例 / 风险

- 用"排除清单"打包：新增敏感目录时默认会漏进去。
- 探针拦"路径字符串"：README 里教用户配置 `VAULTMIND_VAULT` 都写不了，文档报废。

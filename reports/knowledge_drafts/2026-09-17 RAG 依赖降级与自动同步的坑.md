# RAG 依赖降级与自动同步的四个坑

> type: insight
> status: draft
> created: 2026-09-17
> tags: RAG, 依赖降级, 结构分块, 变更检测, 测试假绿
> source: VaultMind 全项目代码审查修复（2026-09-17）
> confidence: high

## 1. 依赖故障降级要覆盖「全链路」，别只包一头

- 现象：`/ask` 里 `search → embed_texts` 已把 httpx 错误包成 `RuntimeError`，但 `generate()` 直接裸抛 `httpx.HTTPError`，而 API 只 `except RuntimeError` → 生成期 Ollama 掉线/上下文超限 = 裸 500。
- 教训：检索、生成、改写三处调用同一上游（Ollama），异常包装要**一致**——要么都包成 `RuntimeError`，要么 API 侧 `except (RuntimeError, httpx.HTTPError)` 双保险。降级「看起来修好了」不等于「每个窗口都修好了」。

## 2. 结构分块：前言也要受 max_chars 约束

- 现象：H2 切分里，首个 H2 之前的「概述」前言用 `emit()`（不切分），而 H3/doc 路径都用 `emit_pieces()`（切分）。一旦某篇前言 > 嵌入模型上下文（bge-m3 num_ctx=4096 ≈ 1500 中文字），`--build-vectors` 直接 HTTP 400。
- 教训：同一条分块管线的**每个分支**都要走同一套长度守卫；漏一个分支 = 埋一颗随内容增长而引爆的地雷。

## 3. 变更检测必须「真正短路」，只打日志是死功能

- 现象：`sync_vault.py` 算了 `changed` 但只用来打印 warn/ok，全流程照跑。
- 教训：写「未变化则跳过」这类优化，要写**测试**证明它真的跳过了（hash 一致 → 不再重建）；否则是自欺。

## 4. 轻量同步与全量同步要隔离指纹

- 现象：若轻量同步（只重建索引+向量）和全量同步（含复验/锚点/PDF/pytest）共用同一指纹文件，轻量同步一落盘，全量同步就会被误判「未变化」而跳过，导致指标/文档永远不更新。
- 教训：不同**代价/范围**的同步动作，各自维护独立状态（`index_state.json` vs `sync_state.json`）。

## 5. 测试假绿：空列表 / 空指纹让断言空转

- 现象：`assert not misses` 在 `edits` 为空时恒真；「不触碰正式向量」在正式向量不存在时前后指纹都是 `(False,None,None)`。
- 教训：断言前先 `assert edits` / 用哨兵文件制造真实前置，保证断言在「有东西可断」的前提下跑。

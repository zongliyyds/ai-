# LLM 引用格式不稳定：解析器先冒烟后定正则

## 核心观点

**LLM 输出格式类功能，先跑真实模型冒烟、收集格式变异，再定解析正则**——单靠想象格式写解析器必返工。

## 实战案例（VaultMind M4，qwen2.5:7b-instruct）

要求模型输出 `[S#]` 引用编号，实测出现 4 种变异：

- 单编号：`[S1]`
- **列表式（首轮冒烟 3/4 FAIL 就是它）**：`[S1, S2, S4]` —— 括号内每个数字都带 S
- 带空格 / 中文分隔：`[S 3]`、`[S1，S3、S5]`
- 中文括号：`【S1】`

## 最终正则（可直接复用）

```python
CITE_RE = re.compile(r"[\[【]([Ss][Ss\d\s,，、]*)[\]】]")
# 内层字符类必须允许重复 S —— 这是踩过的坑：只放 [\d\s,，、] 时
# "[S1, S2, S4]" 提取为空（因为 S2/S4 里的 S 不在字符类）
```

配套探针：把每一种变异写成 pytest 断言，后续换模型/改提示词时回归。

## 反例 / 风险

- 提示词里写"严格输出 [S1][S2]"没用——7B 模型不保证格式稳定，解析器必须宽容。
- 用 `\d+` 只提取括号内数字时，注意 `[W1]`（外部引用编号）与 `[S#]`（占位符）不要误收。

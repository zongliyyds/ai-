# RAG 评测集构建：分层抽样定稿法

## 核心观点

构建 RAG 检索评测集（gold set）时，**候选问题不要用 LLM 生成**（评测与生成同源会自循环），而是从文档结构模板化派生；定稿用**分层抽样 + 可复现算法**，而不是"随手挑 60 条"。

## 方法六步（VaultMind M3 实战，60 条 / 220 候选）

1. **池（pool）**：候选问题从高价值笔记的 H2 标题 + 首句模板化派生（TREC pooling 思想；规避 RAGAS 合成评测集的"自循环"批评）。
2. **分层抽样**：按（库目录 × 难度）分层，最大余数法比例配额、每层 ≥1 条、单文档 ≤3 条——"Coverage, not averages"（分层覆盖优于只看均值）。
3. **问题全局唯一**：同标题模板在多篇文档产生的重复问题文本只保留一条，消除标注歧义（同一问题两个"正确答案"会污染 MRR/nDCG）。
4. **规模 50~200**：本案例取 60 条（arXiv:2601.22025 推荐小型、版本化、跨意图分层的 golden set）。
5. **可复现**：固定随机种子 + 确定性排序，重跑逐字节一致；记录 SHA-256。
6. **校验闸门**：数量/状态/去重/答案文档存在/章节可定位/单文档上限/分层覆盖 + **每条 gold 目标必须能映射回已索引 chunk**（本案例 100%）。

## 适用场景

- 个人/团队知识库、垂直领域检索系统的评测集搭建；需要向别人证明"指标可信"的场合。

## 反例 / 风险

- LLM 直接生成问题 + LLM 判分 = 自我循环，面试/论文一问就穿。
- 同标题模板不做全局去重 → 标注歧义，指标失真。
- 不校验"目标章节真实存在于索引" → gold 里混入检索不到的题。

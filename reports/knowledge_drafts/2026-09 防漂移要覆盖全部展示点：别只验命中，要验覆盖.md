# 防漂移要覆盖全部展示点：别只验命中，要验覆盖

## 核心观点

「单一事实来源 + 现场解析」能消灭**手抄**漂移，但消灭不了**自动回写系统自己的覆盖盲区**。防漂移系统也要被管住：一个数字有几处展示点，回写/读取逻辑就必须覆盖几处——漏一处，那处就静默漂移。而「模式能命中」≠「展示点全覆盖」，探针若只验前者，漏网的点会安静地坏。

## 现象（VaultMind 2026-09-19 实战）

测试数从 79 涨到 84，CHANGELOG 已写「79→84」，但 README、简历 bullet、Q&A 预案、面试 PDF 四处仍钉着「79」：

- 根因：`sync_vault.py` 的 `anchor_edits` 只回写 Q&A 预案的 pytest 数；README 的「pytest N 条 / # N passed」、简历 bullet、PDF 脚本里的「pytest 79 条」都不在回写清单里。
- `test_anchor_patterns_all_match` 只断言「已登记的模式能命中目标文件」，**不校验「所有展示点都被登记」** → 漏网的点静默漂移，探针仍全绿（假绿）。

## 做法

1. **先枚举展示点**：一个数字出现几次，列一张清单（pytest 条数 → README×2、简历 bullet、Q&A 预案、PDF×1）。
2. **能消除复制就别回写**：PDF 这类每次重生的交付物，改成运行时 `count_tests()` 现场统计——让展示点去读真相源，比「回写追着改」更彻底（本次 `/metrics` 从「解析 Markdown」改成「读 `baseline.json`」也是同一动机）。
3. **消不掉的复制才用回写，且覆盖到每一处**：本次把 README 的「pytest N 条」「# N passed」、简历 bullet 的 pytest 数补进 `anchor_edits`。
4. **给覆盖完整性上探针**：不只验「模式命中」，还要能发现「某展示点根本没被登记」。可行做法是让测试显式声明「期望被覆盖的展示点清单」，再断言清单里的每一项在回写列表里都有对应条目。

## 一句话总结

防漂移分两级：**先消除复制**（展示点去读真相源），**再覆盖回写**（消不掉的复制，回写清单要全，探针要验「覆盖完整性」而非只验「命中」）。

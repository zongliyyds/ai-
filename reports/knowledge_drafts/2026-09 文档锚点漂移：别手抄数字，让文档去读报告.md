# 文档锚点漂移：别手抄数字，让文档去读报告

## 核心观点

只要「同一组数字」被复制到两处以上，它就一定会漂移。真正能锁住的不是**纪律**（"记得同步更新"），而是**单一事实来源 + 现场解析**：报告是唯一真值，文档/测试/PDF 都在运行时去读它。

## 现象（VaultMind 2026-09-17 实战）

索引重建事故修复后重建向量，指标变好（MRR 0.7010→0.7096、nDCG@10 0.7339→0.7403、延迟 0.866s→0.253s）。但：

- `reports/baseline.md` 被 eval 重生 → `/metrics` 端点**自动**跟着变（它解析报告文件）
- README 表格、简历 bullet、Q&A 预案、工单、PDF 生成脚本、两处测试断言**仍钉旧数字**
- 结果：`test_api` 先红（断言旧值 vs API 新值），文档对面试官自相矛盾

**触发条件**：任何"重跑一次报告"的动作，都会让所有手抄副本过期。这类漂移不会报错，只会静默地让材料互相打架。

## 做法

1. **锚点集中在报告**：`reports/baseline.md`（指标总表）、`reports/ablation.md`（消融结论）、`reports/baseline_audit.json` + 索引库（规模数字）。
2. **下游一律现场解析**：
   - 测试：`tests/_doc_anchors.py` 的 `parse_report_metrics()` / `parse_ablation_deltas()`，断言"文档里出现的数字 == 报告里的数字"，而不是"文档里有 0.8167"。
   - 交付物生成器：PDF 脚本从 `reports/` 和 `data/vaultmind.db` 取数（规模、指标、分层、消融增益全自动）。
   - 消融总控：报告正文里的"1,237×1024"这类数字也改为 `SELECT COUNT(*) FROM chunks` 动态插入。
3. **解析器要分段**：报告里多张表可能有**同名行**（如 E1 与总览表都有 `hybrid` 行）。按 `## E 段` 限定作用域，否则后出现的同名行会静默覆盖前面的值——我曾因此把 **E4 标题重排的分层值**当成基线分层值。
4. **列数检查会吃表**：E6 表只有 4 列，被通用的 `len(cells) < 6` 检查直接跳过 → 取到默认 0.0。特殊表要在通用检查**之前**分支处理。

## 一句话总结

**数字写一次（报告里），其余地方都去读它**；探针断言"一致性"而不是"具体数值"，这样报告重生时全套材料自动跟随，不会有人掉队。

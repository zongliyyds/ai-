# 消融实验的隔离基建：临时索引 + 基线闸门 + 内容指纹

## 核心观点

「改个配置再跑一遍」不算消融。能下结论的消融需要三件基建：**临时索引路径**（不污染正式库）、**基线复现闸门**（V1 必须精确复现官方数字）、**内容指纹**（证明两个变体的索引到底差在哪）。

## 三件基建（VaultMind M6b 实战）

1. **临时索引路径**：给索引/向量 API 加 `db_path`/`npy_path`/`ids_path` 可选参数，默认值 = 正式路径 → 主链路零改动；每个变体一个独立目录，可断点续跑。配一条探针：**往临时库写入后，正式向量产物的 (exists, size, mtime) 必须不变**。
2. **基线复现闸门**：gating 必须拿「官方基线」比，而不是「上次跑的结果」；不通过就整份报告作废（脚本 exit 2）。
3. **内容指纹**：对**实际进入检索的文本**算 SHA-256。指纹相同 ⇒ 两个变体在检索上必然等价，指标若有差异一定是别的原因。这是防自欺最便宜的武器。

## 配套纪律

- **默认参数 = 正式行为**：改动后用一次性脚本比对「新代码重新分块的 `(rel, seq, section, prefix, text)` 序列」与「正式索引库」——VaultMind 实测 1321 块**逐字节一致**，才算零改动。
- **锚点现场取数**：报告 / PDF / 测试里的基线数字从 `reports/*.md` 解析，不手抄（本轮体检就抓到一处手抄常量已漂移 0.0003，因闸门容差 0.001 未暴露）。
- **单一变量**：各变体的嵌入配置必须一致（同模型、同 `num_ctx`）；为迁就上下文限制而调 `num_ctx` 会让变体不可比。
- **负结果照写**：细粒度 -0.0333、「两因子不叠加」都进报告——负结果与「不叠加」同样是可以讲的结论。

## 一句话面试口径

「消融跑在隔离的临时索引上，有基线复现闸门和内容指纹兜底，所以『提升 0.10』这种数字经得起追问。」

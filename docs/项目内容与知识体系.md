# VaultMind 项目内容与知识体系（给非技术背景的你）

> 这份文档的用途：面试被问「你这个项目是什么、你懂多少、你到底做了什么」时，
> 能**诚实、清晰、有底气**地回答。它不要求你假装懂代码，而是帮你把「你在 AI
> 帮助下做成了什么」这件事讲得专业、可信、有分寸。

---

## 0. 先记住一句话

**这个项目 = 把你的 Obsidian 笔记库（168 篇）变成「会检索、会回答、会给自己打分」的问答系统。**

类比：你原来有一屋子纸质笔记，翻找靠手动；现在给这屋子装了一个
「智能索引员」——你问它，它先在笔记里找出最相关的几段，再让本机大模型
根据这几段组织答案，并且**每条答案都标注是从哪几篇笔记里来的、可以一键跳回去**。
最特别的是：它还配了一套「标准考题 + 自动打分」，能量化地回答「这个系统检索得准不准」。

---

## 1. 大致内容：它到底能干什么（通俗版）

| 功能 | 通俗说法 | 对应代码入口 |
|---|---|---|
| **问答** | 输入问题 → 检索最相关笔记 → 本地大模型带引用回答 | 网页 `http://127.0.0.1:8001` / `vaultmind.ask` |
| **拒答** | 知识库里没有的，明确说「没有」，绝不瞎编 | `vaultmind/llm/validator.py` |
| **检索** | 关键词(BM25) + 语义(向量) 双路找最相关片段 | `vaultmind/retrieval/` |
| **自评** | 60 道标准题自动打分（Recall@5=0.8167 等） | `vaultmind/eval/` |
| **看板** | 库规模、指标、坏例、用户反馈 | `/stats` `/metrics` `/badcases` |
| **一键同步** | 笔记新增/改动 → 一条命令重建索引+向量+复验 | `scripts/sync_vault.py` |
| **体检报告** | 扫描知识库，数出笔记数/字数/死链/孤儿 | `vaultmind/ingest/` |

**一句话收口**：它是一个「检索 + 生成 + 评测」三者闭环的本地优先 RAG 系统，
刻意不用 LangChain / torch / 向量数据库（这是它最大的技术卖点之一，见 §3）。

## 2. 知识体系：它涉及哪些技术（分层「你该懂到什么程度」）

下面把整个项目涉及的技术，按「**面试必须能讲 / 知道存在即可 / 可诚实说 AI 帮实现**」分三档。

### 第一档：核心概念，面试必须能用自己的话讲（不背术语）

1. **RAG（检索增强生成）**
   - 一句话：大模型不联网、不背库，而是「先检索出相关资料 → 把资料塞给模型 → 让它照着资料答」。
   - 为什么这么做：直接问大模型会**编造（幻觉）**；有了检索这一步，答案有据可查。
   - 本项目的落地：检索（§第一档第 3 条）+ 生成（qwen2.5 本地模型）串起来，就是 RAG。

2. **分块（Chunking）**
   - 一句话：一篇笔记太长，检索和模型都吃不下，要切成小块；本系统按「## 标题」为单位切，超 600 字再细分。
   - 你能讲的亮点：我们做了 6 种切法的对照实验，发现「把标题也并进正文」能让检索准确率 +0.10（这是本项目最漂亮的一个结论）。

3. **检索：BM25 关键词（默认）+ 向量语义 + RRF 融合（可选）**
   - BM25：关键词精确匹配（"我要找含『FTS5』这个词的笔记"）——**当前默认模式**，消融实测单路最优。
   - 向量检索：语义相似（"意思相近但用词不同也能找到"），靠 bge-m3 把文字变成 1024 维数字向量。
   - RRF：把两路的排名合并成一份。**消融实测：前缀入检索后 BM25 单路 0.9333 反超融合 0.9167**——所以正式用 BM25，融合/向量保留为可选兜底（不是拍脑袋，是数据）。

4. **评测集 + 指标（Recall@5 / MRR / nDCG@10）**
   - 一句话：给系统出 60 道「标准题」，每道题知道正确答案是哪篇笔记，然后看系统能不能把它排进前 5。
   - Recall@5 = 60 题里「正确答案出现在前 5 名」的比例 = 0.9333（约 56/60）。
   - 关键卖点：这 60 题是**从笔记结构规则化派生的、不是用大模型编的**（防止"自己出题自己答"的自欺）。

5. **消融实验（Ablation）**
   - 一句话：把系统某个零件关掉，看分数涨跌，从而证明「这个零件到底有没有用」。
   - 本项目做过的：关掉向量只留关键词、关掉融合、换查询改写、换分块粒度……结论有正有负，**负结果也如实记录**（这是加分项：说明不吹）。

### 第二档：知道「它存在、解决什么问题」即可，不必会写

- **SQLite FTS5 + jieba 分词**：本地文件型数据库 + 中文分词工具，负责「关键词怎么拆、怎么存、怎么搜」。
- **numpy 暴力点积**：没有用向量数据库，直接用数学库算相似度。规模曲线实验证明「在 1.3k 块这个量级，暴力算 <1ms，够快」。
- **FastAPI + 原生前端**：把功能包成网页接口；前端是单个 HTML 文件，零构建。
- **Ollama 本地模型**：bge-m3（转向量）+ qwen2.5:7b（生成回答），都跑在本机，不联网、不花钱、不泄隐私。
- **pytest + pre-commit 钩子**：84 条自动化测试 + 提交前自动拦坏提交，是「改不坏」的保险丝。

### 第三档：可诚实说「这部分 AI 帮我实现，我理解到 XX 程度」

- 具体代码怎么写、正则怎么配、PDF 怎么渲染、bat 怎么不秒退——这些**细节**完全可以诚实说
  「实现层面是 AI 辅助完成的」。面试官真正想确认的是**第一档那些概念你懂不懂**，
  以及**你作为「负责人」做了什么决策**（见 §4）。

## 3. 你的真实角色：不是「写代码的人」，是「负责人 + 决策者」

> 很多非技术背景的同学最大的错误是：要么吹「全是我写的」→ 一追问就穿帮；
> 要么怂「都是 AI 做的，我啥也没干」→ 把自己的真实价值也丢了。**两个都别走。**

你真实做了、且面试完全站得住的事情：

1. **定义方向与需求**：提出「把我的知识库做成可问答、可评测的求职作品」，并定下
   「本地优先 + 云端兜底」「AI 应用 + 数据分析双方向」的目标。
2. **立规矩（红线）**：只读知识库、数字必须可复现（不许编）、隐私（本地优先）、
   不开源笔记内容。这些不是技术细节，是**工程判断**。
3. **做决策**：每一个「候选方案」最终采不采纳，是你拍板的。最典型的例子——
   消融实验发现「前缀入检索能 +0.10」，但没有擅自改正式管道，而是**等你决策**；
   这正是负责人该有的克制。
4. **验收与追问**：每个里程碑都有验收标准，你按标准验收；你还会**反问**
   （"为什么有些题答不好？"），驱动 AI 去查根因、去对照实验——这是「提好问题」的价值。
5. **维护质量底线**：坚持负结果也记录、坚持每个数字都有出处、坚持换机能复现。

**一句话总结你的角色**：你是这个项目的**产品经理 + 验收负责人**，AI 是**实现工程师**。
面试时这句话本身就能打动人，因为它说明你懂「人和 AI 怎么分工」。

## 4. 面试话术模板（照着改，别照背）

**Q：这个项目是你自己写的吗？**
> 「需求、方案决策、验收是我主导的，具体代码实现是我在 AI 协作下完成的。
> 我更愿意讲清楚我做的决策和它为什么这么做——比如我们坚持不用 LangChain，
> 是因为 1.3k 块的规模暴力检索就够快，引入框架反而增加不可解释性。」

**Q：你懂 RAG 吗？**
> 「懂核心链路。RAG 就是先检索再生成、避免模型瞎编。我的系统里，检索是
> BM25+向量的混合、生成走本地 qwen、再用 60 题 gold 集量化评测。细节实现
> 我让 AI 做，但『为什么这么选』是我定的。」

**Q：AI 帮你做了多少？**
> 「实现细节大部分是 AI 写的，但『做什么、做到什么标准、采不采纳』是我的判断。
> 最体现我价值的是决策：消融实验证明有个改动能 +10% 准确率，我没有盲目上，
> 而是先评估代价再拍板——这种克制和验证意识，才是这个项目教会我的东西。」

**Q：这个项目里你最有把握讲清楚的一个技术点？**
> 建议选 **§2 第一档第 4 条「评测集」** 或 **第 5 条「消融」**——这两个最能体现
> 「严谨」而非「会写代码」，也最不容易被追问到代码细节。

## 5. 三不原则（保命提醒）

1. **不背不理解的名词**：任何你答不上的术语，宁可说「这个我记的是 XX，让我查一下」，
   不要硬编——面试官追问两轮就穿帮，比诚实说「不记得」扣分更多。
2. **不夸大也不贬低**：「全是我写的」会穿帮，「都是 AI 做的」会埋没你——用 §3 的分工话术。
3. **数字只报有出处的**：本系统每条数字都能在 `reports/` 里找到并重跑复现，
   被追问时直接指路 `reports/baseline.md`，这是你最大的底气。

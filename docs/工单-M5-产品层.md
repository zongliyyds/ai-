> 节点：M5 产品层（W3 第一块）｜ 前序：M1~M4 已完成（检索三模式 + gold 基线 + 生成链路）
> 状态：**已完成**（2026-09-16：pytest 44/44 + 在线冒烟 6 端点全过，详见 §5 结果记录）

## 0. 范围界定

- M5 只做**产品层**：把已验证的 `search()` + `vaultmind.llm` 包成可演示的 Web 应用。
- 检索/生成的**算法不改一行**——M3/M4 数字保持可复现；算法改动归 M6 消融。
- 前端**零依赖**：原生 HTML+CSS+JS，图表用 CSS 条形图（不引 CDN——本机境外 CDN 多不可达，换机可用优先；Chart.js 可选后加）。

## 1. 子步骤与交付物

| # | 内容 | 交付物 |

| S1 | FastAPI：`/health`、`/search`、`/ask`（复用 search+context+generate+validate，返回引用清单与校验结果）、`/stats`、`/metrics`、`/badcases`、`/feedback` | `vaultmind/api/main.py`、`vaultmind/api/stats.py` |

## 2. 验收标准（写之前就知道"什么叫做完"）

1. **离线探针全绿**：TestClient 覆盖全部端点（检索/生成打桩，不依赖 Ollama）；`/metrics` 数字与 `reports/baseline.md` 精确一致（Recall@5=0.8167、MRR=0.7010、nDCG@10=0.7339）；`/badcases` 条数=11；`/stats` 数字与数据库直查一致；pytest 全量通过。
2. **在线冒烟**：启动 `run_api.bat`（或 uvicorn）→ `/health` 200、`/` 返回问答页 HTML、`/ask` 真模型一问返回可追溯引用、`/stats` 数字与 DB 一致。
3. **浏览器可用（人工验收）**：打开 `http://127.0.0.1:8000`，问"CET-4 项目用了什么去重方案"，答案正确、引用能点开对应笔记（Obsidian 跳转）。
4. **红线零违反**：服务只读 Vault 与派生索引；日志只写 `data/vaultmind.db`；无云端调用；问题文本仅本地处理。

## 3. 红线（叠加通用红线）

- 只读 Vault（立项书红线 ①）；`qa_logs` 属于派生产物（`data/`，gitignore）。
- 生成结果默认**不落盘**（除问答日志外不保存答案全文——日志只存长度与编号，防隐私冗余）。
- 引用跳转走 `obsidian://open` URI（浏览器禁 file:// 跨源跳转；Obsidian 已装本机）。

## 4. 风险预案

| 风险 | 预案 |
|---|---|
| 浏览器里 obsidian:// 跳转被拦截 | 引用项同时显示 vault 相对路径文本，可手动定位 |
| 7B 生成 8~15s，Web 体验慢 | `/ask` 同步返回但前端显示"生成中"；延迟如实展示（面试可讲 decode 限速与 M6 云端对比） |
| /metrics、/badcases 依赖报告文件 | 端点实时解析 `reports/baseline.md`（报告入 git，随版本走）；文件缺失返回明确错误 |
| uvicorn 后台跑丢 | `run_api.bat` 一键启动 + smoke 脚本验收 |

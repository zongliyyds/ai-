# 工单 M3-01：评测集（gold 60 条，人工定稿）+ 指标基线

> 节点：M3 评测集 + baseline 指标（W2 第一块）｜ 前序：M1/M2 已完成（检索三模式可用）
> 状态：**开工中**（AI 生成候选池与指标代码 → 你人工筛选定稿 60 条 → 跑基线）
> 红线（立项书 M3）：**gold 集禁止由 LLM 直接定稿**，必须人工过一遍——否则评测自我循环，面试一问就穿。

## 1. 人机分工（本工单核心）

| 谁 | 干什么 |
|---|---|
| AI | ①候选问题生成器（模板化，不用 LLM，从笔记 H2 结构派生）②指标公式手写实现（numpy，不引 ragas）③评测 runner + CLI ④种子草稿集（标 draft，仅供预览） |
| 你 | 从候选池筛选/改写 **60 条** → 逐条标 `approved`；AI 不代签 |

## 2. 子步骤

| # | 内容 | 产出 |
|---|---|---|
| S1 | 候选问题生成器 | `scripts/gen_candidates.py` → `eval/candidates.jsonl`（模板化问题池，约 150~250 条） |
| S2 | gold 集结构 | `eval/gold_set.jsonl`：`{id, question, answer_points[], docs[], section, status: draft|approved}` |
| S3 | 指标实现 | `vaultmind/eval/metrics.py`：Recall@1/5/10、MRR、nDCG@10、平均延迟（公式手写） |
| S4 | 评测 runner + CLI | `python -m vaultmind.eval` → `reports/baseline.md`（逐题明细 + 指标表，可复现） |
| S5 | 指标探针 | `tests/test_eval.py`（构造已知排序 → 断言精确值，防公式写错） |

## 3. 验收标准（写之前就知道"什么叫做完"）

1. 指标公式单元探针全绿（已知排序 → 精确数值）。
2. `gold_set.jsonl` ≥ 60 条且**全部 `approved`（你定稿）**。
3. 一条命令 `D:\python\python.exe -m vaultmind.eval` 输出指标表，重跑结果一致。
4. 红线零违反：gold 无 LLM 定稿；指标不伪造；Vault 只读。

## 4. 候选生成策略（防自欺）

- 来源：入链 Top 笔记 + 体量 Top 笔记 + 各类型/目录覆盖抽样；
- 问题只从笔记 **H2 标题 + 首句** 模板化派生，不用 LLM 生成问题（避免评测与生成同源）；
- 每条候选带 `docs`（正确答案笔记）+ `source_doc` + `section`，供你快速核对。

## 5. 你的定稿操作

1. 打开 `eval/candidates.jsonl`（或我导出的 `reports/candidates_review.md` 可读版）；
2. 挑 60 条：改写成真实会问的话、补 `answer_points` 要点、修正 `docs`；
3. 把选中的条目（`status` 改为 `approved`）放进 `eval/gold_set.jsonl`（或告诉我"按某某清单批准"，我代填后你复核）；
4. 完成后说"gold 已定稿"，我跑基线并进入 M4 生成链路。

## 6. 风险预案（钩子已就位）

| 风险 | 预案 |
|---|---|
| 候选池质量差（问题太模板化） | 你改写时顺手口语化；改写率本身就是"人机协同标注"的简历素材 |
| 指标公式写错 | S5 探针用已知排序断言精确值，错一票红灯 |
| 评测运行慢 | 10 条 × hybrid（向量点积毫秒级），全量 <10s |
| 基线不达标 | 如实记录（目标值先测后调），把缺口留给 M6 消融优化 |

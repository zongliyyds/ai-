## 0. 定稿方式变更记录（重要，面试口径）

- 原方案：60 条由用户人工筛选改写。2026-09 用户主动授权改为：**AI 参考互联网现有评测集构建做法，以透明、可复现的算法定稿**（`scripts/finalize_gold.py`），用户事后复核报告。
- 不变的底线：候选问题仍**只用笔记 H2 结构模板化派生，不用 LLM 生成问题/判分**；定稿过程全部规则化（分层抽样 + 配额 + 去重 + 校验闸门），固定种子重跑逐字节一致（SHA-256 记录在案）。
- 复核入口：`reports/gold_finalization.md`（方法 + 文献 + 分配表 + 60 条清单 + 闸门结果）；`reports/baseline.md`（逐题明细）。

## 1. 人机分工（本工单核心）

## 2. 子步骤

| # | 内容 | 产出 |
|---|---|---|
| S1 | 候选问题生成器 | `scripts/gen_candidates.py` → `eval/candidates.jsonl`（模板化问题池，约 150~250 条） |
| S2 | gold 集结构 | `eval/gold_set.jsonl`：`{id, question, answer_points[], docs[], section, status: draft|approved}` |
| S3 | 指标实现 | `vaultmind/eval/metrics.py`：Recall@1/5/10、MRR、nDCG@10、平均延迟（公式手写） |
| S4 | 评测 runner + CLI | `python -m vaultmind.eval` → `reports/baseline.md`（逐题明细 + 指标表，可复现） |
| S5 | 指标探针 | `tests/test_eval.py`（构造已知排序 → 断言精确值，防公式写错） |

## 3. 验收标准（写之前就知道"什么叫做完"）

1. 指标公式单元探针全绿（已知排序 → 精确数值）。
2. `gold_set.jsonl` = 60 条且**全部 `approved`**（算法定稿 + 报告复核，见 §0）。
3. 一条命令 `D:\python\python.exe -m vaultmind.eval` 输出指标表，重跑结果一致。
4. 红线零违反：gold 问题无 LLM 生成/判分；定稿可复现；指标不伪造；Vault 只读。

## 4. 候选生成策略（防自欺）

- 来源：入链 Top 笔记 + 体量 Top 笔记 + 各类型/目录覆盖抽样；
- 问题只从笔记 **H2 标题 + 首句** 模板化派生，不用 LLM 生成问题（避免评测与生成同源）；
- 每条候选带 `docs`（正确答案笔记）+ `source_doc` + `section`，供你快速核对。

## 5. 定稿结果（2026-09-16 完成）

- 命令：`D:\python\python.exe scripts\finalize_gold.py --seed 42`（重跑逐字节一致）
- 结果：60 条 approved（easy 36 / hard 24，覆盖 42 篇文档）；8 道校验闸门全绿（含 chunk 可追溯率 100%）；SHA-256 `7057c373…f2bab`
- 正式基线（hybrid, top_k=10）：Recall@1=0.6167 / **Recall@5=0.8167** / Recall@10=0.8333 / **MRR=0.7010** / **nDCG@10=0.7339** / 平均延迟 0.866s —— 三项目标值（≥0.80 / ≥0.65 / ≥0.70）全部达标。
- 坏例账本（M6 素材）：11 题未进 Top-5，10 题为"裸标题"hard 型（「## 背景」「## 理由」等无语境查询），1 题 easy（MEMORY 长期指令）。easy 档命中 ≈97%，hard 档 ≈58%。

> 节点：M6 消融（W3 第二块）｜ 前序：M5 产品层完成（人工验收通过）
> 状态：**已完成**（2026-09-16：pytest 50/50 + 六组实验跑完，基线复现闸门通过，详见 §5 结果记录）

## 0. 范围界定与实验纪律

- **同一把尺**：全部实验跑同一份 60 条 gold（`eval/gold_set.jsonl`）、同一指标口径（Recall@1/5/10、MRR、nDCG@10、平均延迟），另报 easy/hard 分层指标（坏例账本说 hard 档 ≈58% 是主要瓶颈）。
- **只动待测组件，其余冻结**：改 RRF k 就不动重排；改查询就不动检索。
- **基线 = M3 官方数字**（hybrid k=60：0.8167/0.7010/0.7339/0.866s），每张表首行必须是它。
- **分块粒度消融不在本次范围**：需要临时索引路径 + 重嵌入基建（~1.2k chunks × 2 变体），列为 M6b 第二阶段，避免污染正式索引。
- 所有变体通过 `search()` 的**可选参数**实现（默认值=基线行为，默认路径零改动，M3 数字不受影响）。

## 1. 六组实验

| # | 实验 | 变量 | 预期关注点 |

## 3. 验收标准

1. pytest 全绿（新增消融纯函数探针；既有 44 条回归不破）。
2. `reports/ablation.md` 含六张表，**每张首行=基线数字**（0.8167/0.7010/0.7339 精确复现），全部实验可一条命令重跑：`D:\python\python.exe scripts\m6_ablation.py`。
3. 每组给出结论句（增益/无增益/负增益 + 一句话归因），不粉饰负结果。
4. 红线零违反：所有实验只读索引与报告；LLM 改写仅用本地模型；不写 Vault。

## 4. 风险预案

| 风险 | 预案 |
|---|---|
| LLM 改写引入幻觉词反而掉分 | 如实报告（这也是结论）；改写提示词强制"不添加任何新信息" |
| 实验总时长（多次全量向量检索 + 24 次 LLM 改写） | 后台任务运行，报告生成时间如实记录；E6 用矩阵切片免重嵌入 |
| 1-hop 扩展引入噪音 | 扩展块分数置底 + 数量上限，报告 net 效果 |
| 基线被变体污染（同进程跑多次） | 各实验独立调用 search()，无全局状态；正式基线数字另从 reports/baseline.md 校验 |

## 5. 结果记录（2026-09-16 完成，详见 reports/ablation.md）

- pytest **50/50**（新增 6 条消融纯函数探针）；基线复现闸门**通过**（hybrid 行与官方 0.8167/0.7010/0.7339 精确一致）。
- **E1 三路单拆**：hybrid 0.8167 > bm25 0.7667 > vector 0.7500（R@5）；但 hybrid R@1=0.6167 **低于** vector 0.6667 → 量化了「顶部稀释」现象。
- **E2 RRF k**：k∈{20,60,100} R@5 恒 0.8167、MRR 极差 0.0012 → 参数不敏感，无需调参。
- **E3 查询改写（负结果）**：规则版 -0.0167、LLM 版 -0.0667，hard 档 0.5833→0.5417→0.4167 一路下降 → **查询侧改写不上线**。
- **E4 标题重排（混合结果）**：总体 -0.0667，但 easy 1.0000 / hard 0.3750 分层撕裂 → **需条件化（标题命中才加权）**。
- **E5 1-hop 扩展（中性）**：R@5 +0.0000、MRR -0.0019 → 不进检索主链路，转 Web 侧「相关笔记推荐」。
- **E6 规模-延迟曲线**：vector 25%→100% 语料 290→286ms 持平 → 瓶颈是查询侧 embedding（~280ms），暴力点积 <1ms → **零向量库决策被验证**；bm25 仅 ~3ms。
- 遗留：M6b（分块粒度消融，需临时索引路径基建）未做，列入 W4 追加实验。
